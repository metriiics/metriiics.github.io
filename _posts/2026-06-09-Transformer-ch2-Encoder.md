До появления трансформеров основой большинства NLP-систем были рекуррентные нейронные сети(RNN). Такие архитектуры обладали рядом ограничений.

Главная проблема заключалась в последовательной природе вычислений. Для обработки текущего токена сети необходимо было сначала вычислить скрытое состояние для всех предыдущих токенов. Из-за этого обучение плохо масштабировалось на современные вычислительные устройства и практически исключало эффективную параллельную обработку последовательностей[2]. #### Трансформеры. Архитектура Encoder
Трансформеры, представленные в 2017 году в статье *Attention Is All You Need*, предложили принципиально иной подход. Вместо последовательной обработки токенов модель использует механизм внимания (Attention), позволяющий каждому элементу последовательности напрямую взаимодействовать со всеми остальными. В предыдущей части мы рассмотрели механизм позиционного кодирования (Positional Encoding). Теперь перейдем к центральному компоненту архитектуры — блоку Encoder и лежащему в его основе механизму Self-Attention.

#### Механизм самовнимания
Для начала рассмотрим базовый механизм внимания, не затрагивая пока концепцию Multi-Head Attention. На рисунке 3 иллюстрируются главные компоненты блока кодировщика.
<figure>

<figcaption>Рис. 3. Визуализация главных компонент блока энкодера</figcaption>
</figure>

Основная идея Self-Attention заключается в том, что при обработке каждого токена модель должна определить, какие другие токены последовательности наиболее важны для формирования его представления.

Для этого вводятся три обучаемые матрицы параметров:
- \\( W_q \\)(omega query) - последовательность запросов;
- \\( W_k \\)(omega key) - последовательность ключей;
- \\( W_v \\)(omega value) - последовательность значений.

Пусть на вход поступает векторное представление токена \\x\\ размерности \\d_{model}\\.
Тогда для каждого токена вычисляются три новых представления:

$$  
\begin{align*}
Q = xW_Q  
\\
K = xW_K  
\\
V = xW_V 
\end{align*}
$$

где:
- Query определяет, какую информацию ищет текущий токен;
- Key описывает, какую информацию содержит токен;
- Value хранит данные, которые будут переданы дальше после вычисления внимания.

Под тензором query можно понимать запрос — то есть вопрос: к кому нам следует обратиться?
Под тензором key понимается ключ, который указывает на нужное значение и как бы «говорит» query: взаимодействуй со мной.
Тензор value представляет собой сами значения.

Интуитивно этот механизм можно сравнить с поиском по базе данных.

Представим hashtable:
```
{"banana": "banana is yellow product"}
```

Вы задаете вопрос - "What is banana?". 

В данном случае ваш вопрос выступает в роли Query. Ключ "banana" соответствует Key, 
а текстовое описание — Value. Вы задали вопрос(Query): Query взаимодействовал с Key и определил, какое значение (Value) вам нужно.

#### Алгоритм внимания
Первым шагом в расчете внимания является создание трех векторов из каждого входного вектора, как обсуждалось ранее. То есть для каждого слова мы создаем вектор запроса, вектор ключа и вектор значения. Эти векторы создаются путем умножения встраивания на три матрицы, которые мы обучили во время тренировочного процесса. На рисунке 4 показан первый шаг алгоритма.
<figure>
<img src="/assets/img/transformer2/img4.png" alt="Формирования Q, K, V">
<figcaption>Рис. 4. Формирования Q, K, V</figcaption>
</figure>

Для демонстрации создадим эмбеддинги двух слов - любовь(love) и кошка(cat):
```python
love = torch.randn(64)
cat = torch.randn(64)
```

Инициализируем обучаемые матрицы \\( Q, K, V \\): 
```python
W_q = torch.randn(64, 64)
W_k = torch.randn(64, 64)
W_v = torch.randn(64, 64)
```

После проводим матричное умножение и получаем вектора \\( q1, k1, v1 \\) и \\( q2, k2, v2 \\).
```python
q1 = torch.matmul(love, W_q)
k1 = torch.matmul(love, W_k)
v1 = torch.matmul(love, W_v)

q2 = torch.matmul(cat, W_q)
k2 = torch.matmul(cat, W_k)
v2 = torch.matmul(cat, W_v)
```

Второй шаг в расчете - вычисление оценки. Оценка определяет, сколько внимания следует уделять другим частям входного предложения, когда мы кодируем слово в определенном положении.

Для этого вычисляется скалярное произведение между Query текущего токена и Key всех токенов последовательности.
```python
score1 = torch.dot(q1, k1)
score2 = torch.dot(q1, k2)
```

Полученные значения называются Attention Scores. На рисунке 5 показан второй шаг алгоритма.
<figure>
<img src="/assets/img/transformer2/img5.png" alt="Вычисление Attention Scores">
<figcaption>Рис. 5. Вычисление Attention Scores</figcaption>
</figure>

Третий и четвертый шаг: С ростом размерности векторов значения скалярных произведений начинают быстро увеличиваться. Это приводит к насыщению функции Softmax и ухудшению прохождения градиентов.

Для решения этой проблемы в оригинальной статье вводится коэффициент масштабирования.

> Коэффициент масштабирования - \\( \frac{1}{\sqrt d_k} \\).
> 
> Этот коэффициент компенсирует рост дисперсии скалярных произведений при увеличении размерности ключей \\( d_k \\). Благодаря этому масштабированию, значения, поступающие в softmax остаются в разумном диапазоне, что предотвращает появление малых градиентов[2].

Масштабируем данные, объединяем скоры и получаем функцию softmax.
```python
div1 = score1 / math.sqrt(k1.shape[0])
div2 = score2 / math.sqrt(k1.shape[0])

scores = torch.stack([div1, div2])

softmax = F.softmax(scores, dim=0)
```

После масштабирования оценки преобразуются в вероятностное распределение. В результате веса внимания суммируются в единицу. На рисунке 6 продемонстрированы третий и четвертый шаги алгоритма. 
<figure>
<img src="/assets/img/transformer2/img6.png" alt="Масштабирование и Softmax">
<figcaption>Рис. 6. Масштабирование и Softmax</figcaption>
</figure>

Пятый и шестой шаги умножают каждый вектор значения на оценку softmax. И проводят суммирование векторов. Это приводит к выходному слою внимания.

Теперь мы умножаем каждый вектор \\( V \\) на коэффициент функции softmax. И в конечном итоге получаем нашу матрицу \\( Z \\), которая является выходом данного слоя.
```python
weight1 = v1 * softmax[0]
weight2 = v2 * softmax[1]

Z = weight1 + weight2
```

Именно этот вектор передается на следующие уровни сети. На рисунке 7 представлены пятый и шестой шаги алгоритма.
<figure>
<img src="/assets/img/transformer2/img7.png" alt="Формирование выходного вектора">
<figcaption>Рис. 7. Формирование выходного вектора</figcaption>
</figure> 

Если объединить все шаги в единую запись, получим классическую формулу масштабированного скалярного внимания(рисунок 8). 
<figure>
<img src="/assets/img/transformer2/img8.png" alt="Итоговая формула Self-Attention">
<figcaption>Рис. 8. Итоговая формула Self-Attention</figcaption>
</figure>

Важно понимать, что механизм внимания - это квадратичная сущность, которая строит матрицу взаимодействий между всеми токенами последовательности.
Другими словами, Self-Attention блок строит матрицу попарных взаимодействий между всеми токенами последовательности. Каждый элемент этой матрицы показывает, насколько один токен должен обращать внимание на другой.

\[
\begin{bmatrix}
q_1 \cdot k_1 & q_1 \cdot k_2 \\
q_2 \cdot k_1 & q_2 \cdot k_2
\end{bmatrix}
\]

#### Multi-Head Attention
Теперь вернемся к понятию многоголового внимания (Multi-Head Attention)(рисунок 9).
<figure>
<img src="/assets/img/transformer2/img9.png" alt="Архитектура Multi-Head Attention">
<figcaption>Рис. 9. Архитектура Multi-Head Attention</figcaption>
</figure>

На практике *Multi-Head Attention* можно рассматривать как набор из N механизмов внимания. Каждый такой механизм принято называть «головой», отсюда и термин «многоголовое внимание».

Это расширение позволяет модели одновременно фокусироваться на разных аспектах входной последовательности и учитывать зависимости между различными позициями.

В рамках многоголового внимания каждая голова имеет собственные обучаемые матрицы:

$$  
\begin{align*}
W_Q^i; W_K^i; W_V^i  
\end{align*}
$$

и обучается извлекать различные аспекты контекста. На рисунке 10 демонстрируется пример множества матриц многоголового внимания.

<figcaption>Рис. 10. Множество матриц многоголового внимания</figcaption>

Если выполнить вычисления внимания отдельно для каждой головы (например, при 8 головах), то на выходе мы получим 8 матриц результатов.

#### Add & Normalize
Чтобы двигаться дальше по архитектуре, необходимо прояснить ещё один её блок(рисунок 13).
<figure>
<img src="/assets/img/transformer2/img13.png" alt="Визуализация блока Add & Normalize">
<figcaption>Рис. 13. Визуализация блока Add & Normalize</figcaption>

Блок Add & Normalize состоит из двух частей: 
- Add - Residual Connection(она же остаточная связь, skip connection). 
- Normalization

Остаточная связь позволяет сохранить старую информацию и добавить к ней новую.
Операция нормализации - стабилизирует распределение признаков и делает процесс обучения более устойчивым.

В оригинальном Transformer использовалась схема Post-LN, которую мы описали выше[1].

Однако в современных архитектурах чаще используется подход *Pre-LN*, при котором слой нормализации переносится перед блоком *Multi-Head Attention*, тогда как остаточная связь остаётся без изменений.
Исследования показали, что такой подход обеспечивает более стабильное обучение глубоких трансформеров[3]. На рисунке 14 демонстрируется вариант с Pre-LN архитектурой.

#### Feed Forward Network(FFN)
После блока Attention идет слой нейросети. Блок Feed Forward Network - нейросеть, которая состоит из двух полносвязных слоев, разделенных нелинейностью. Первый слой увеличивает размерность, в то время как второй уменьшает ее обратно. 
Увеличиваем, чтобы преобразовать полученную информацию от Attention в более сложные комбинации признаков, а затем возвращаем к размеру модели. На рисунке 15 показана архитектура Feed Forward Network.
<figure>
<img src="/assets/img/transformer2/img15.png" alt="Архитектура FFN">
<figcaption>Рис. 15. Архитектура FFN</figcaption>
</figure>


FFN можно считать базой знаний, именно в этой структуре хранится 2/3 всех параметров модели.

#### Summary
Attention -> определяет, на какую информацию из контекста смотреть.

FFN -> преобразует эту информацию, используя знания, закодированные в параметрах модели.
